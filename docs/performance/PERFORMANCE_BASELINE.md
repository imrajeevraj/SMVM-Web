## 1. Executive Summary

A comprehensive performance, bundle composition, network waterfall, rendering, and Core Web Vitals audit was conducted across the SMVM Softwares website.

### Critical Baseline Findings:
1. **Single Monolithic JavaScript Bundle:** Vite builds the entire application into a single JavaScript file (`dist/assets/index-cgJPMwbh.js`, **652.81 kB raw / 184.48 kB gzip / 155.73 kB brotli**) due to eager static imports for every single page in `src/App.tsx`.
2. **Single Monolithic CSS Bundle:** All 17 page-specific CSS files are combined into one single stylesheet (`dist/assets/index-aEnxZR2L.css`, **455.02 kB raw / 77.13 kB gzip / 60.97 kB brotli**). A visitor landing on the homepage downloads styling for CamStore, About, Services, Legal, and CamBill.
3. **Massive Unoptimized Image Payloads:**
   - Homepage transfers **19.52 MB** on desktop and **8.76 MB** on mobile.
   - Services overview transfers **16.66 MB** on desktop and **6.85 MB** on mobile.
   - 71 uncompressed PNG files in `public/images/` total **94.66 MB**, with individual card images reaching up to **2.24 MB**.
   - Many components in `src/` still point directly to `.png` paths rather than modern `.webp` versions.
4. **Mobile Long Tasks and Total Blocking Time (TBT):**
   - Under 4x CPU mobile throttling, initial JavaScript evaluation and hydration generate long tasks exceeding 50ms, resulting in TBT up to **1,342 ms** on `/products/camstore-pos` and **755 ms** on Homepage.
5. **No Route-Level Code Splitting:**
   - 0 dynamic `React.lazy` imports.
   - The floating chatbot conversation engine is eagerly parsed and mounted on every single page load even when unopened.

## 5. Root Cause Analysis of Identified Bottlenecks

1. **Large Photographic PNGs Loaded Instead of WebP:**
   - Multiple pages reference `.png` images that are between 1.5 MB and 2.24 MB each.
   - Example: On Homepage, `hero-retail-showroom.png` is 1.71 MB. Switching to `hero-retail-showroom.webp` (148 KB) will reduce transfer by 91.3% while preserving full visual quality.
2. **Missing `srcset` / Responsive Dimensions:**
   - On mobile devices (390px width), desktop-sized images (1920px wide) are downloaded, wasting bandwidth and memory.
3. **Missing `loading="lazy"` on Below-the-Fold Imagery:**
   - Cards, features, and footer-adjacent sections load immediately upon initial document parse, competing with above-the-fold assets.
4. **Lack of Priority Hints for LCP:**
   - The hero image lacks `fetchpriority="high"`, causing it to wait in the browser network queue behind secondary assets.
5. **Monolithic Bundle (Zero Code Splitting):**
   - Eager imports in `App.tsx` prevent route-level lazy loading.
   - Every user pays the parse, compile, and execution tax of Framer Motion animations and markup for all 24 pages on their initial landing page.
6. **Chatbot Component Eager Loading:**
   - Chatbot markup and logic are loaded and hydrated on every route even if the user never opens the chatbot modal.
